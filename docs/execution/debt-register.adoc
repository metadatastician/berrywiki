= BerryWiki — Debt Register
:toc: macro
:toclevels: 2

toc::[]

Known debt, by kind. Every entry states what is wrong, what it costs, and what
would clear it. Entries are removed when fixed, not marked done — the
link:work-packages.adoc[work-package register] tracks progress; this file
tracks *liabilities*.

Compiled 2026-08-07 during a full documentation audit; revised 2026-09-02 with
Gate 0 (P3-serve-sync, X-lock, P0-ledger, P2-move, P3-conflict). Items marked
*CLEARED* were fixed in that same pass and are listed only so the history is
legible; they will be deleted at the next revision.

== Severity

[cols="1,4", options="header"]
|===
| Level | Meaning
| *H* | Actively misleads a user, or risks data/legal exposure. Fix before the next release.
| *M* | Wrong or absent, with a real cost, but nobody is misled into harm.
| *L* | Tidiness, consistency, or a cost that only maintainers pay.
|===

== Licence debt

[cols="1,5", options="header"]
|===
| Sev | Item

| *CLEARED*
| `Cargo.toml` declared `license = "MIT OR Apache-2.0"` while `LICENSE` and
  `README` said MPL-2.0 + CC-BY-SA-4.0. All eleven crates inherit
  `license.workspace = true`, so every crate would have published under the
  wrong terms. Ruled 2026-08-07: **MPL-2.0 for code, CC-BY-SA-4.0 for docs**.
  `berrywiki.launcher.a2ml` carried the same wrong claim and was corrected.

| *CLEARED*
| `LICENSES/AGPL-3.0-or-later.txt` existed with no referent. Its origin was
  `.github/settings.yml`, copied from another project with an AGPL header.
  Deleted along with the AGPL headers that pulled it in.

| *CLEARED*
| No REUSE metadata and no SPDX headers: 0 of 31 Rust files, 0 of 22 Markdown
  files. `REUSE.toml` now maps every path to a licence and all Rust sources
  carry headers.

| M
| REUSE compliance is *declared but never checked*. Nothing in CI runs
  `reuse lint`, so the mapping can rot silently. Clearing it: add a REUSE
  lint step to `ci.yml`. Until then, treat REUSE.toml as documentation, not
  as a verified property.

| L
| `LICENSE` at the repository root concatenates a prose summary with the full
  MPL-2.0 text. GitHub's licence detector reports "other" rather than
  MPL-2.0 as a result. Clearing it: keep `LICENSE` as the bare MPL-2.0 text
  and move the dual-licensing explanation to `README`/`REUSE.toml`.
|===

== Repository hygiene

[cols="1,5", options="header"]
|===
| Sev | Item

| *CLEARED*
| **`.github/settings.yml` was paint-type's**, and the probot/settings app
  applies that file on every push to the default branch. It would have
  renamed this repository to `paint-type`, replaced its description with an
  image editor's, repointed its homepage, and set `has_wiki: false` —
  disabling the wiki on a project whose entire purpose is GitHub wikis.

| *CLEARED*
| **Security reports were routed to the wrong project.** The "Report a
  vulnerability" link in `.github/ISSUE_TEMPLATE/config.yml` pointed at
  `metadatastician/paint-type/security/advisories/new`. Eleven files under
  `.github/` carried paint-type references; all repointed.

| *CLEARED*
| `.github/funding.yml` and `.github/FUNDING.yml` both existed — a case
  collision that breaks checkouts on case-insensitive filesystems (Windows,
  default macOS). The uppercase one also had duplicate YAML keys (`github:`,
  `ko_fi:` and four more, each twice), so most of its entries were silently
  discarded by the parser.

| *CLEARED*
| `api/zig-unified-hexdeca-api/` shipped a 45-line Zig program that prints
  "Server listening on port 8080 (Scaffold)" without listening to anything.
  It was in no build, referenced by no CI, and contradicted ADR-0003.

| *CLEARED*
| `ARCHITECTURE.md` and `MAINTAINERS` listed **@metadatastician as a
  co-architect / co-maintainer**. It is the owning organisation account, not
  a person.

| *CLEARED*
| `berrywiki-launcher.sh` and `berrywiki.launcher.a2ml` were undocumented,
  untested, and could not have started the application: a hardcoded
  absolute config path, a search for a binary named `berrywiki-cli` that no
  build produces (and a `[ -x name ]` test that never consults `$PATH`), an
  icon at a nonexistent `assets/` path, and a start command with no
  `serve <folder>` argument. Fixed 2026-09-02 by hand (the generator,
  `launch-scaffolder`, is not on the host); README section added;
  `scripts/check-launcher.sh` runs in CI with a fake binary and asserts the
  exact argv.

| L
| The launcher pair is now hand-maintained. `berrywiki-launcher.sh` still
  says "GENERATED"; its header lists the four properties a future
  `launch-scaffolder realign` must preserve, but nothing enforces that
  beyond `scripts/check-launcher.sh` catching a regression after the fact.

| L
| The desktop entry `--integ` writes runs through
  `/var/mnt/eclipse/repos/.desktop-tools/keepopen.sh`, an estate-absolute
  path from the launcher standard that does not exist on this host, and a
  menu entry does not see the shell environment that carries
  `BERRYWIKI_WIKI`. Both are stated in the README; the `--start`/`--stop`/
  `--status` arms work from a terminal. Clearing it: a launcher-standard
  ruling on the fallback ladder, and a per-user config file for the wiki
  folder (not built; the environment variable is the whole mechanism today).

== Code debt

[cols="1,5", options="header"]
|===
| Sev | Item

| M
| The stale guard fingerprints mtime + length. An edit that preserves both
  within one filesystem tick is undetectable. Documented in ADR-0008;
  clearing it means upgrading to a content hash.

| M
| `berrywiki-github` is read-only, so `serve --github` cannot edit. The
  editor works only against a local folder. Since P3-serve-sync the crate
  docs fence it as mirror-only; the Team write path is `berrywiki-sync`
  over a managed clone, not this crate.

| M
| `serve` runs git on the request path: a checkpoint + commit per save and
  a fetch + push on `POST /sync`. With the single-threaded server a slow
  remote blocks every other request for the duration. Acceptable for one
  user on loopback; the push-off-the-request-path worker is P7-sync-worker.

| L
| The `/changes` page lists the last 50 commits and the `/conflicts` page
  renders a hand-off and, for a merge the operator started, the classified
  clash with all three sides, but neither is reachable from the native GitHub
  reader; nothing about their content is a live-GitHub claim. Whether a
  wiki remote accepts the fast-forward push shape is still P3-spike-write.

| L
| `crates/berrywiki-serve/src/ids.rs` mints UUIDv7-shaped ids from
  `RandomState` and the pid. Uniqueness is sound in practice; the values are
  *not* unpredictable. That is fine — page ids are public identifiers — but
  nothing must ever come to depend on their unguessability.

| L
| Page ids are minted in `berrywiki-serve` while `berrywiki-store` documents
  id generation as the application layer's job. A second writing front end
  would need to duplicate or share that code.

| L
| There is no offline three-way preview of a diverged but unmerged history.
  `/conflicts` can classify only a merge the operator has already started,
  because the classification reads git's index stages; before that there is
  nothing to read, so the operator learns which pages clash only after
  running `git merge`. Deliberately not built: a preview would be a
  *prediction* of what git would do rather than a fact taken from the index,
  and producing it would widen `berrywiki-git`'s closed literal set. Clearing
  it is a ruling, not a task.

| L
| The `no_script` helper is duplicated in
  `crates/berrywiki-serve/tests/editor.rs` and
  `crates/berrywiki-serve/tests/sync.rs`, and both copies are naive substring
  probes: lowercase the response, then assert it contains none of `<script`,
  `javascript:`, `onerror=` or `onclick=` (the last two each preceded by a
  space). Escaped page text that merely contains an attribute-looking
  substring trips them, which forced a test payload change during P3-conflict
  rather than a fix to the probe. Clearing it: one shared helper that inspects
  elements and attributes instead of raw substrings.
|===

== Proof debt

[cols="1,5", options="header"]
|===
| Sev | Item

| M
| **There are no proofs.** The README's technology note has referenced a
  "mathematically sound base" and SPARK/GNATprove since Phase 0, but no
  `.gpr` project, no `gnatprove` lane and no proof obligations exist. The
  invariants that would be proved are now written down as a ledger,
  `docs/proofs/invariants.adoc` (INV-1..6, each naming its witnessing tests,
  CI-checked by `scripts/check-invariants-ledger.sh`), and are covered by
  tests only. Tracked as *P5-spark*. Until then, no document may describe any
  BerryWiki property as "proved"; 259 passing tests are evidence, not proof.

|===

== CI/CD debt

[cols="1,5", options="header"]
|===
| Sev | Item

| *CLEARED*
| Two action pins in `ci.yml` referenced commits that do not exist upstream,
  so **every run died at action download for eight days**. Repointed, along
  with a latent `dtolnay/rust-toolchain` failure (a SHA pin cannot infer the
  toolchain from the ref).

| *CLEARED*
| CodeQL default setup and an advanced `codeql.yml` were both configured — a
  combination in which GitHub rejects the advanced workflow's uploads. Ruled:
  keep default setup, delete the advanced workflow.

| *CLEARED*
| `dependabot.yml` declared mix, npm, pip and nix ecosystems with no matching
  manifests, producing failing update jobs on a Rust-only repository.

| H
| **`pages.yml` has never succeeded.** Its only run — 2026-07-19 — was a
  `startup_failure` at 0 seconds, and it has not been triggered since. GitHub
  Pages is enabled and publishing from a workflow, so the site is
  permanently empty. Its canonical base URL also named the wrong owner
  (`hyperpolymath.github.io` for a repo in `metadatastician`); that is fixed,
  but the workflow itself remains unproven.

| M
| `pages.yml` builds `src/index.md`, falling back to a copy of `README.md`.
  There is no `src/`, so a successful run would publish the README as a
  single page. Either give the site real content or remove the workflow and
  disable Pages — an empty published site is worse than none.

| M
| The lint job is the *only* gate that runs `rustfmt` and `clippy`, and it
  never executed until 2026-08-03. Its first real run found four defects.
  Both now run locally (host toolchain and the 1.89 podman recipe), but
  nothing enforces them before a commit; CI is still the only hard gate.

| M
| No REUSE lint, no link checker, no MSRV-drift check beyond the 1.89 matrix
  leg, and no coverage measurement.

| L
| The SonarCloud step was removed from `ci.yml` because no
  `sonar-project.properties` and no `SONAR_TOKEN` were configured — it could
  never have reported anything. Restore it properly or leave it out.
|===
