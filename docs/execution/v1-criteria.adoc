Until now nothing defined "v1". The only release gate was *MVP-declare*, which
cuts `v0.1.0` (link:../architecture/implementation-plan.adoc[implementation
plan], Phase 5 exit criteria). This document defines what `v1.0.0` must
additionally show. It is written so that *every criterion is a check that can
fail*: each names the evidence that satisfies it, and "we believe so" is never
that evidence.

== Release line

. *`v0.1.0`, MVP-declare.* Unchanged: the Phase 5 exit criteria and the
  MVP-declare package. It is the first tag, and it is a prerequisite here.
. *`v0.x`.* Each criterion below lands as its own increment, with the default
  branch green when it does.
. *`v1.0.0`.* Every row below is *met*, or *waived by a recorded owner ruling*
  that names the row and gives the reason. A row that is merely "nearly met"
  blocks.

== How a criterion is judged

* *Met* means the named evidence exists, can be re-run, and was produced at the
  candidate commit or after it. A count from `grep`, a warm `target/`, or a
  green check that has never been shown to fail does not qualify.
* Every automated gate cited here must carry a *planted negative*: a known-bad
  input that the gate is shown to reject, in CI.
* Numeric thresholds marked _(proposed)_ are the owner's to set. They are not
  met by being reported close.

== Criteria

Ordered by the project's charter priorities.

=== R: real-world verification

[cols="1,4,4,1", options="header"]
|===
| ID | Criterion | Evidence that satisfies it | Now

| R1 | A real CherryTree notebook, grown in actual use, imports cleanly. | The import report and the resulting commit for an owner-supplied notebook; source hash unchanged; the tree is browsable in the native GitHub wiki. *Owner-only:* needs the notebook. | ❌
| R2 | Every row of the compatibility report is evidence-backed or explicitly waived. | `github-wiki.adoc` has no ❓ row without an owner waiver. Open today: repository size limit, token-authenticated push. | ❌
| R3 | Heading-fragment navigation is verified in a real browser. | A recorded browser run (scripted or manual) against the spike wiki for both fragment forms, written into the report. | ❌
| R4 | BerryWiki is in use on at least one wiki it did not create, and `berrywiki check` passes there. | A named repository (candidate: `hyperpolymath/blocky-writer`, issue #61) with a `berrywiki check` run recorded at a stated commit. | ❌
| R5 | The full CI suite, including the manual-dispatch live job, is green at the candidate commit. | The run IDs. | ❌
|===

=== S: security and adversarial robustness

[cols="1,4,4,1", options="header"]
|===
| ID | Criterion | Evidence that satisfies it | Now

| S1 | A written threat model covers every surface: the HTTP server, parsers of untrusted input (Markdown, the metadata block, CherryTree XML, multipart upload, request line and headers), the filesystem, git, the GitHub mirror and credentials. | `docs/architecture/threat-model.adoc`, reviewed against the route table and the crate list. | ❌
| S2 | The local server refuses cross-origin and rebinding attacks. | Tests that plant a cross-site `POST` (foreign `Origin`), a foreign `Host` header, and the `/\host` redirect form, each refused, and that fail when the check is removed. | ❌ (no Origin or Host check exists today)
| S3 | No single client can stall the server. | Read and header timeouts, and a size limit on header lines, each with a test that holds a slow or short connection open. | ❌
| S4 | Credentials never leave their intended destination. | The token is sent only to `https://github.com`; the askpass helper is created exclusively in a private directory; tests cover a non-GitHub remote, an `http://` remote, and a pre-planted helper path. | ❌
| S5 | No command can destroy work outside BerryWiki's own state. | `berrywiki-github` refuses a cache directory it did not create; the destructive-command audit covers every crate; the audit tests carry a planted negative. | ❌
| S6 | Every untrusted-input parser is fuzzed. | A `fuzz/` target per parser in S1; at least _(proposed)_ 24 CPU-hours cumulative per target with zero unexplained crashes; committed corpora; a short fuzz run on every pull request. | ❌
| S7 | Dependencies are audited. | `cargo-deny` (advisories, licences, bans, sources) and `cargo-audit` in CI, both clean, each with a planted negative. | ❌
| S8 | No open High or Medium security finding. | The debt register and `dev-notes` findings list contain none, unless an owner ruling waives one. | ❌
|===

=== T: tests that can fail

[cols="1,4,4,1", options="header"]
|===
| ID | Criterion | Evidence that satisfies it | Now

| T1 | Each invariant INV-1 to INV-6 has property-based tests as well as example tests. | Property tests named in `invariants.adoc` next to the existing witnesses. | ❌
| T2 | The test suite catches real defects. | `cargo-mutants` over core, store, sync, serve, git and render: a caught rate of at least _(proposed)_ 90%, with each surviving mutant either killed or listed as equivalent, with a reason. | ❌
| T3 | Every self-check is shown to fail. | A planted negative for the served-script detector, the invariants-ledger script, the source audits (`git/tests/audit.rs`, `sync/tests/structural.rs`) and each CI gate. | 🟡 some exist
| T4 | Crash safety is tested under injected failure. | Tests that inject write and fsync failures and interleave writers, and that show no torn or lost page. | ❌
|===

=== P: packaging, release and stability

[cols="1,4,4,1", options="header"]
|===
| ID | Criterion | Evidence that satisfies it | Now

| P1 | `v0.1.0` exists (MVP-declare met). | The tag and release. | ❌ (blocked on P5-guix)
| P2 | The packaging route builds, reproducibly. | Under ruling D-12(b), a Guix package built in CI. *Owner decision needed:* `guix` is absent from the maintainer's machine, so either install it or amend D-12(b). | ❌
| P3 | Release artefacts are signed and verifiable. | `SHA256SUMS` plus a minisign signature, the public key published, and a documented verify step that is shown to reject a tampered file. | ❌
| P4 | A new user can install from the release alone. | The install guide followed on a clean machine, with a transcript. | ❌
| P5 | The on-disk format is stable and versioned. | The metadata block carries a version; the v1 format is frozen; an upgrade test reads every earlier fixture. | ❌
| P6 | A versioning policy is published. | A SemVer statement that says what counts as breaking (CLI flags, routes, the metadata format). | ❌
| P7 | Backup and restore are proven. | A round-trip on a real-sized wiki (_(proposed)_ 2,000 pages), with the restored tree byte-identical. | 🟡 tested on fixtures
|===

== Not required for v1

Zim import and the other P6 importers; SPARK proofs (the invariants are
*tested*, not *proved*, and v1 says so); the generated-script enhancement layer
(ADR-0007); full-text search at scale; the Team and Enterprise profiles, unless
M1 rules otherwise.
