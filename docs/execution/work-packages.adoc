= BerryWiki Work-Package Register
:toc: macro
:toclevels: 2
:sectnums:

toc::[]

Each work package is a unit of executable work tagged with the Claude tier that
should run it and the triggers that force an escalation. Tiers map to the agent
definitions in `.claude/agents/` (`berrywiki-opus`, `berrywiki-sonnet`,
`berrywiki-haiku`). The phase structure follows
link:../architecture/implementation-plan.adoc[the implementation plan] — which
is a *critic-reviewed draft*: packages that a critique-appendix finding gates
carry a *Blocked-by* note and must not start until that finding is resolved.

== Tiering principle

[cols="1,3,2", options="header"]
|===
| Tier | Gets | Escalates when
| *opus* | irreversible / subtle: sync engine, conflict UX, transactional
subtree move + link rewriting, rich-editor round-trip, import semantics, SPARK,
live-spike interpretation | never — this is the top tier; instead it *slows
down* and proves
| *sonnet* | scoped builds against a settled design: UI panes, search, read
explorer, CI/packaging, importer plumbing | the work touches git history / data
safety, needs a subtree cascade, contradicts an ADR, or leans on an unverified
GitHub assumption
| *haiku* | mechanical, checklist-driven: fixtures, doc/report sync, lint,
boilerplate, ADR skeletons, search-and-replace | any judgement, ambiguity, test
failure it cannot mechanically fix, or contact with git/sync/data safety
|===

== Phase 2 — In-app editing + drafts (still user-pushes-with-git)

[cols="1,1,4,3", options="header"]
|===
| ID | Tier | Contract | Escalation triggers / Blocked-by

| P2-edit | *DONE* | Source editor + preview; create/update/delete via the
store; explicit Save / Save-draft with visible unsaved state (banner, badge,
nav dot). Zero-JS forms + 303 PRG; a refused Save keeps the text in the form
AND as a draft. Two-layer stale guard: store fingerprint (ADR-0008) + hidden
`base` source-hash per editor session. Drafts wired through appstate
(`berrywiki-serve::App`); degraded visibly when appstate is unresolvable. |
Former blocker resolved by ADR-0006 (explicit Save-draft, no autosave
promise). X-lock (below) now guards the serve process, which is a
long-running writer.
| P2-move | *DONE* | Engine and UI. The store cascades descendant filenames,
rewrites inbound links, regenerates the sidebar and recovers a crashed move on
open; sync lands it as one commit. `GET /page/<id>/move` offers a new parent
(never the page itself or its own subtree) and a position; **Preview** is a
pure dry run (`LocalFolderStore::plan_move`) listing every rename and link
rewrite without writing anything; **Move** re-plans against the live graph
and applies, so a stale preview can never be applied. A hidden base
(`from_parent` / `from_position`) turns a form opened before another move
into a 409. Titles are deliberately not part of a move: the title is the
page's H1, changed in the editor, and the filename follows it on the next
move (ledger INV-5: `plan_move_is_a_pure_dry_run_of_the_cascade`,
`nonleaf_move_through_the_form_is_one_commit_with_the_sidebar`). | Any change
to the cascade itself, or a move that would touch git history, → stop.
| P2-stale-guard | *DONE* | Store fingerprints (mtime+len) every file at load;
update/delete/move refuse a `StaleWrite` if a file changed on disk since load.
Critique major resolved (ADR-0008). | Blind spot: an edit preserving both mtime
and length within one tick (documented) → content-hash upgrade if it bites.
| P2-app-state | *DONE* | `berrywiki-appstate`: XDG-state home keyed by a stable
repo hash for drafts/journal/lock/index; `RepoLock` (OS advisory lock, see
X-lock).
Nothing app-private in the clone. Critique major resolved (ADR-0008). | Wire the
search index + draft dir through it when those land.
| X-lock | *DONE* | **Done 2026-09-02.** `berrywiki_appstate::RepoLock`: OS
advisory lock (`std::fs::File::try_lock`, Rust 1.89, hence the MSRV bump) on
`<state>/lock`, held for the life of `serve` and around `sidebar --write`
(the only two CLI writers today; `check` is read-only and takes no lock). A
second writer exits 2 naming the holder; the holder record is diagnostic only
and never consulted for acquisition (no reclaim); the OS releases the lock on
process death. Unresolvable app state degrades to a warning. Evidence: two-
process test in `crates/berrywiki-appstate/tests/lock.rs`, CLI refusal test.
| Never add reclaim logic (ADR-0008). Cross-host locking is a hosted-deployment
question, not this package.

== Phase 3 — In-app sync (commit / pull / push / conflict)

[cols="1,1,4,3", options="header"]
|===
| ID | Tier | Contract | Escalation triggers / Blocked-by

| P3-gitengine | *DONE* | `berrywiki-git`: `GitRepo` over a *closed* set of git
invocations; history-overwriting / working-tree-discarding operations
*unrepresentable* — proven structurally by a source-scan audit test (needles
live in the test, not the scanned source, so no false-positive) AND
behaviourally (a rejected push leaves the remote tip asserted-unchanged).
`LC_ALL=C`, porcelain `-z`, hermetic config, `GIT_TERMINAL_PROMPT=0`, explicit
identity, `with_env` credential seam. ADR-0009. 11 behavioural + 2 audit tests
vs. `GitSandbox`. | Validated against a local bare remote only (ADR-0002);
live-GitHub auth/rejection shape is P3-spike-write.
| P3-sync | *DONE* | `berrywiki-sync`: `SyncedStore` wraps store+engine.
Commit-on-save = one atomic logical commit per mutation (sidebar in the same
commit, `add -A` on a precondition-clean tree). `ensure_committable` refuses a
detached HEAD / in-progress merge and checkpoints ordinary dirt as its own
commit WITHOUT reloading (keeps StaleWrite live). `refresh`/`advance`/`sync`/
`sync_retrying` run fetch→integrate(ff)→push; a genuine divergence returns
`Diverged(DivergedHandoff{local,upstream,base,ahead,behind})` untouched — no
merge, no ff, no push, remote unchanged. ADR-0010; 16 behavioural + 1 structural
test vs `GitSandbox`. | Live-GitHub write path is P3-spike-write. Edit UI (P2)
and conflict resolution (P3-conflict) still consume this.
| P3-conflict | *DONE* | **Done 2026-09-02.** Classification reads the git
index of a merge the *operator* started, never the working tree: `ls-files -u`
plus `show :1:`, `:2:` and `:3:` give ancestor, ours and theirs, which is what
makes the body-versus-metadata split decidable (the working tree holds a
marker-laced blend of both sides). Kinds: `Sidebar`, `Body`, `Metadata`,
`AddedBoth`, `DeletedByThem`, `DeletedByUs`, `Opaque`. Page bodies and metadata
are surfaced with all three sides and are never merged or unioned; only the
generated `_Sidebar.md` is auto-settled, by reloading the store and
regenerating it from the settled page set before the merge commit is recorded.
`SyncError` gained `MergeInProgress` (a mutation is refused while an operator's
merge is unfinished) and `NoMergeInProgress`. `MergeInProgress` displaces
`UnmergedPaths` whenever `MERGE_HEAD` is present; `UnmergedPaths` stays
reachable for an unmerged index with no merge under way (a halted cherry-pick)
and keeps its own witness test. `/conflicts` shows the three sides per file and
`POST /conflicts/finish` concludes a sidebar-only merge. No `<script>` on any
new path. ADR-0010 Consequences amended to record that the enum did change.
Evidence: `crates/berrywiki-sync/tests/conflict.rs` (9 tests) and the
P3-conflict section of `crates/berrywiki-serve/tests/sync.rs` (6 tests), both
over `GitSandbox`. | Inherently opus. Metadata conflicts are surfaced, never
unioned. Any change that would merge two authored sides on the user's behalf
-> stop.
| P3-serve-sync | *DONE* | **Done 2026-09-02.** `serve` holds
`SyncedStore<LocalFolderStore>` by default: every editor create/save/delete is
one logical commit, sidebar in the same commit; outside changes checkpointed
first; `/changes` (pending state, last 50 commits, `POST /sync` = fetch +
fast-forward + push, never merge, never force), `/conflicts` (hand-off with
manual steps), status strip, fixed `notice` tokens. `serve --no-commit` opts
out; a non-git folder degrades to that with a warning; `--author` sets the
identity. `berrywiki-github` fenced as mirror-only. Default port 23779 (TCP
only, loopback), per the estate network policy. Evidence:
`crates/berrywiki-serve/tests/sync.rs` over `GitSandbox`. | Any change
that would merge, reset or force on the user's behalf → stop. Token text
must pass `redact_secret` on every rendered path. P3-spike-write runs
*after* this so the spike exercises the real path.
| P3-spike-write | opus | Live-GitHub *write-side* spike: concurrent push
rejection, conflict shape, default branch. | Credential-gated; never fake.
|===

== Phase 4 — Tags, history, attachments, accessibility

[cols="1,1,4,3", options="header"]
|===
| ID | Tier | Contract | Escalation triggers
| P4-tags | sonnet | *DONE* — **Done 2026-09-02.** `tags:` is a list key in the
metadata block, so the native GitHub reader ignores it and an older build
preserves it. One combined store method `update_page_with_tags` keeps a body+tag
save to a single commit on the synced backend. `/tags` counts pages per tag;
`/tags/<tag>` lists them; `/search?tag=` filters, alone or beside `q=`; the
editor and the new-page form carry a tag field whose parser trims, drops empties
and drops duplicates. The store validates and never normalises: a tag that would
not round-trip is refused and nothing is written. | git contact → opus.
| P4-history | sonnet | *DONE* — **Done 2026-09-02.** `GitRepo::history` reads
`git log` for one repository-relative path, passing it after `--` so a filename
that begins with a dash can never be read as an option. A path git has never
seen yields an empty list, not an error, so a page saved with commit-on-save off
is a page without revisions rather than a failure. `/page/<id>/history` resolves
the id through the store first, so what reaches the engine is the store's own
path and never a fragment of the URL, and every page carries a last-edited
footer naming the author and date. A page that was moved has a history that ends
at the move; the page says so rather than implying otherwise. | git contact →
opus.
| P4-attach | sonnet | *DONE* — **Done 2026-09-03.** Recorded in
link:../decisions/0011-attachments.adoc[ADR-0011]. An attachment lives at
`assets/<page-id>/<filename>`, linked from the page by an ordinary relative
Markdown link that the native reader resolves; only the emitted href is anchored
at the root, never the Markdown on disk. `multipart/form-data` is parsed by hand
because the workspace keeps one third-party crate. The served content type comes
from a nine-extension allowlist keyed on the filename, never from the upload's
declared type and never sniffed; `svg`, `html`, `htm`, `js` and `xml` are absent
on purpose, because a bytes response is invisible to `no_script`. Two size caps,
1 MiB on the file and 8 KiB of envelope headroom on the whole body, so the
file-sized check can actually fire. Filenames are validated by the store's own
`validate_component`, and `read_attachment` now applies it on the way out too:
`resolve` alone would have read `a/b.pdf` as two valid components, a file
`add_attachment` could never have written. Duplicates are a 409, never an
overwrite; the asset route answers one undifferentiated 404. Both script-free
sweeps gained `sweep_response`, which branches on the response kind and asserts a
content-type allowlist held separately in each test module; all four plants
fired. The attachment-conflict integration test and the absent delete route are
scheduled in the debt register, not built here. | conflict-flow contact → opus.
| P4-a11y | sonnet | *DONE* — **Done 2026-09-03.** Recorded in
link:../decisions/0012-accessibility.adoc[ADR-0012]. The structural half is a
gate: `crates/berrywiki-a11y` is a pure, dev-only crate of fourteen rules that
rides `sweep_response` in *both* script-free sweeps, so it adds no third route
list to forget to update. Writing it found a route that was in neither list,
`GET /page/<id>/delete`, an unswept rendered surface behind two green tests that
each called themselves "every route"; it is now in the sync list. Four
exemptions are deliberate and each is bounded by a test that removes the
exemption's condition and asserts the rule returns. The renderer normalises
headings by a constant shift so the shallowest authored heading lands at `h2`,
rather than demoting by one: a page opening `## Section` would otherwise render
`h1` then `h3` and turn ordinary authoring into a level skip. A source that
skips a level still skips it, because the pass shifts rather than repairs. The
shell gained a skip link, an id on `<main>` and a name on `<aside>`; the draft
dot and the archived state gained visually-hidden text, since colour and shape
announce nothing; three foreground colours were darkened and the contrast ratios
are recorded by hand in the ADR. Seven plants fired, one binary at a time. The
walkthrough half is *not* done and is not claimed:
link:a11y-walkthrough.adoc[the keyboard and NVDA script] is written and
**unexecuted**, because it needs a person at a browser and no automated gate
substitutes for it. | walkthrough execution → owner.
| P4-backup | sonnet | *DONE* — **Done 2026-09-03.** Recorded in
link:../decisions/0013-backup-and-restore.adoc[ADR-0013]. `berrywiki backup
<folder> <out-dir>` writes a directory, not an archive: a `git bundle --all`, a
copy of the drafts and the operation journal, and a MANIFEST. A directory is
readable with git alone, which is the same constraint the wiki itself obeys, and
it costs no new format code. A bundle carries committed history only, so backup
refuses a dirty tree and names each pending path rather than producing an
archive that silently omits the work it was asked to protect. The search index
is excluded as derived data and the lock as a process artefact, both asserted
positively because nothing about copying a directory ever fails on its own.
`berrywiki restore <backup-dir> <folder>` clones from the bundle, then either
repoints `origin` at the recorded URL or drops it, because a clone taken from a
bundle otherwise carries a remote that vanishes with the backup. Drafts are
written back through `AppState::for_wiki(<new folder>)`: `repo_id` hashes the
wiki's path, so restoring to a different directory is a different state dir and
copying to the source's path would produce real files the restored wiki never
reads. Credentials are stripped from the origin URL before it reaches the
MANIFEST, since a backup is a file that gets copied. No timestamp is recorded,
so two backups of an unchanged wiki compare equal. Four assertions were
plant-tested one at a time and all four fired. Writing it found that the git
audit scan does not exempt comments: the engine may not name `reset`,
`checkout`, `restore` or `clean` even in prose, which also makes `checkout-index`
unrepresentable and leaves cloning from the bundle as the only restore path.
**This is the plan's P6-backup as well** — the contract is listed twice — so
`P8-backup-fleet` now has its dependency satisfied. | —
|===

== Phase 5 — Import, packaging, MVP declaration

[cols="1,1,4,3", options="header"]
|===
| ID | Tier | Contract | Escalation triggers
| P5-import-ct | opus | *DONE* -- **Done 2026-09-03.** Recorded in
link:../decisions/0014-cherrytree-import.adoc[ADR-0014]. `berrywiki import
<notebook> <wiki>` reads a CherryTree XML notebook, plans, and prints; `--apply`
writes. The lossiness table in the ADR is the contract: every construct is
either carried or dropped with a named diagnostic, and the report prints the
tally, so a user knows what they lose by count before they decide to apply.
Format is detected by content, so a password-protected or SQLite notebook is
refused with the conversion advice rather than a parse error 4,000 bytes into a
binary file. Every page carries a `source:` marker naming the file hash and the
node, and the page id derives from that same marker, so a second run reports
every page unchanged and writes nothing -- including when the user has since
edited the bodies, which are keyed out of the comparison deliberately and left
alone. Three refusals fire before the first write (sibling title collision, a
page that exists without this node's marker, a folder that is not a git working
tree) and there is no `--overwrite`; a dry run works against a plain folder
because the git requirement is about writing, not reading. The whole import is
one commit with the source hash in the message, and the source file is re-read
and re-hashed afterwards so "we did not touch your notes" is a measurement.
Import is CLI-only: serve's body cap is 2 MiB against notebooks of tens of
megabytes, so an `/import` route needs a streaming reader that does not exist.
71 import-crate tests plus 15 end-to-end CLI tests against real git. |
Conversion semantics are subtle -> opus. Report is AsciiDoc, not Markdown
(critique minor).
| P5-import-zim | sonnet | Zim importer reusing the neutral model + writer. |
Escalate novel conversion semantics → opus.
| P5-guix | opus | Guix package (estate-primary) + Nix fallback; correct
runtime-dep mechanism for `git`; a CI Guix lane. | *Blocked-by* critique major
"Guix under-sized / CI only builds Nix".
| P5-spark | opus | Differential SPARK proofs of the invariants ledger
(`docs/proofs/invariants.adoc`, INV-1..6; metadata
grammar → forest builder → move state machine); nothing labelled "proven"
without a green `gnatprove` CI lane. | Post-MVP; inherently opus.
|===
