= BerryWiki — Invariants Ledger
:toc: macro
:toclevels: 2

toc::[]

This is the single list of properties BerryWiki is built to keep. Each
invariant states what must hold, names the crate that enforces it, and names
every Rust test that currently *witnesses* it. Nothing in this file is
proved. The word "proof" in the directory name records where the SPARK work
of P5-spark / P9-spark will land, not a claim about today: every status
below is **tested, proof scheduled**, and the
link:../execution/debt-register.adoc[debt register] rule that no document
may describe a BerryWiki property as "proved" applies to this one as well.

== How this file is checked

CI reads this file. `scripts/check-invariants-ledger.sh` extracts every
witness row, that is every table row of exactly the shape

----
| `crates/<crate>/<path>.rs` | `<test_fn>`
----

and fails the build unless, for each row: the file exists; a function of
that exact name is declared in it; and the name appears as a registered test
in the output of `cargo test --workspace -- --list`. It also fails if any
invariant section has no witness row at all, and if the extracted set is
empty. A renamed or deleted test therefore breaks CI until this ledger is
updated, so the ledger cannot silently rot.

Rows in the tables below carry only that two-column shape so the extraction
is a declared convention rather than a guess.

== Proof scope

The SPARK target (implementation plan §"Proof targets") is the I/O-free
`berrywiki-core` crate plus two small kernels from `berrywiki-store`: the
metadata grammar (INV-1), the forest builder (INV-2), sidebar generation
(INV-3), the path-safety kernel `validate_component` (INV-6), and the move
state machine with the git argv constructor (INV-5, and the argv half of
INV-4). Everything that touches a real filesystem, a real git process or a
real socket is **test-only for good**: it is witnessed by behavioural tests
against sandboxes and will never carry a proof claim. The table below makes
that split explicit per invariant.

[cols="1,3,2", options="header"]
|===
| Invariant | Proof target (scheduled) | Test-only for good
| INV-1 | metadata parse/serialise in `berrywiki-core` | store byte-preservation, editor round trip
| INV-2 | forest builder in `berrywiki-core` | store reload, move refusal
| INV-3 | sidebar generator in `berrywiki-core` | write-if-changed, clobber refusal, sync commit shape
| INV-4 | git argv constructor (closed literal set) | every behavioural git, sync, lock and editor test
| INV-5 | move state machine (plan → apply → recover) | crash recovery on a real filesystem, atomic commit
| INV-6 | `validate_component` in `berrywiki-store` | symlink, collision and redirect behaviour
|===

== INV-1 — Metadata round-trip idempotence

*Statement.* For any page text, `serialise(parse(text))` is a fixed point:
serialising a parsed block and parsing it again yields the same block and
the same bytes. Unknown keys and their values survive the round trip
unchanged. Malformed values degrade to a diagnostic and never destroy the
block or the page body.

*Enforced in.* `berrywiki-core` (`metadata.rs`); byte-preservation through
the store and the editor.

*Status.* Tested, proof scheduled (P5-spark: metadata grammar).

== INV-2 — Hierarchy acyclicity and deterministic sibling order

*Statement.* The parent relation over pages is a forest: no page is its own
ancestor. A parent reference that would create a cycle, or that names a
missing page, is reported as a diagnostic and the page is placed at the
root; the builder always terminates. Siblings are ordered by `position`
with a total, deterministic tie-break, so two builds over the same pages
walk the tree in the same order.

*Enforced in.* `berrywiki-core` (`graph.rs`); the store refuses a move that
would create a cycle before anything is written.

*Status.* Tested, proof scheduled (P5-spark: forest builder).

== INV-3 — Sidebar determinism

*Statement.* `_Sidebar.md` is a pure function of the page set: the same
pages produce byte-identical output on every run, archived pages are
excluded, and the generated file is rewritten only when its content would
change. A page titled "Sidebar" can never clobber the generated file, and
every tree mutation regenerates the sidebar in the same commit. Concluding a
merge BerryWiki did not start regenerates the sidebar from the settled pages
before the merge commit is recorded, never merging the two authored copies.

*Enforced in.* `berrywiki-core` (`sidebar.rs`); write-if-changed and
clobber refusal in `berrywiki-store`; same-commit rule in `berrywiki-sync`.

*Status.* Tested, proof scheduled (P5-spark: sidebar generator, as part of
the forest builder target).

== INV-4 — Never lose local work

*Statement.* No operation BerryWiki performs can discard uncommitted or
unpushed local content. The git engine cannot express a force-push, a
history rewrite or a working-tree discard; a rejected push leaves the
remote and the local commit intact; a diverged history is handed off
without any merge; a file changed on disk since it was loaded is refused as
a stale write rather than overwritten; outside edits are checkpointed as
their own commit before any save commit; a refused editor save keeps the
typed text; a merge BerryWiki did not start is never absorbed into a
checkpoint commit, and concluding it is refused while any page is still
unsettled; and a second writer on the same clone is refused while the
first holds the lock.

*Enforced in.* `berrywiki-git` (closed literal set, audited by source
scan), `berrywiki-git-compat` (harness), `berrywiki-sync`,
`berrywiki-store` (stale guard), `berrywiki-appstate` (lock),
`berrywiki-serve` (409 path).

*Status.* Tested; only the argv constructor is a proof target. The
behavioural half of this invariant is test-only for good.

== INV-5 — Never half-moved

*Statement.* A subtree move or rename is all-or-nothing: descendant
filenames are cascaded, inbound links are rewritten so they still resolve,
the sidebar is regenerated, and the whole change is one commit. If the
process dies mid-move, opening the store completes or reverts the move
before any read is served, and a file edited by hand after the crash is
never overwritten by the recovery.

*Enforced in.* `berrywiki-store` (move journal and recovery on open);
`berrywiki-sync` (single atomic commit).

*Status.* Tested, proof scheduled (P5-spark: move state machine). Crash
recovery on a real filesystem is test-only for good.

== INV-6 — Path safety (root containment)

*Statement.* Every path the store reads or writes stays inside the wiki
root. Page ids and attachment names are validated as single components:
traversal (`..`), separators, empty and hostile components are rejected
before any filesystem call. A symlink planted at a temporary or page path
cannot redirect a write outside the root, and symlinked pages are ignored
on reload. Case-insensitive filename collisions are suffixed rather than
merged.

*Enforced in.* `berrywiki-store` (`paths.rs::validate_component` and the
atomic-write path); `berrywiki-serve` (redirect targets stay local).

*Status.* Tested, proof scheduled (P5-spark: path-safety kernel). Symlink
behaviour on a real filesystem is test-only for good.

== Adjacent properties that are not invariants

Two tested properties are deliberately *not* numbered here because they are
doctrine, not data-safety invariants, and each already has a gate of its
own: the script-free rendering rule (ADR-0003; `every_synced_route_is_script_free`,
`hostile_input_stays_inert_across_all_editor_surfaces`,
`raw_html_block_never_emits_a_live_script`) and render determinism
(`rendering_is_deterministic`). They are listed so a reader does not go
looking for INV-7.
